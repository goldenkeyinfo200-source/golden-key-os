Golden Key OS — Мурожаатларни таҳрирлаш ва ўчириш

Алмаштириладиган файллар:
1) crm/src/pages/CasesPage.jsx
2) backend/src/routes/cases.js

Қўшилди:
- Мурожаатлар жадвалида "Амаллар" устуни.
- "Таҳрирлаш" тугмаси.
- "Ўчириш" тугмаси.
- Таҳрирлашда:
  Ф.И.Ш., телефон, ЖШШИР, паспорт, туғилган сана, манзил,
  хизмат тури, сумма, хизмат ҳақи, банк ва кейинги ҳаракат ўзгаради.
- Тасдиқланган шартнома мавжуд бўлса хизмат турини ўзгартириш блокланади.
- Ўчиришда икки босқичли тасдиқ:
  1) confirmation
  2) мурожаат IDсини қайта киритиш
- DELETE ҳуқуқи backendда фақат SUPER_ADMIN ва DIRECTOR учун.
- PATCH ҳуқуқи SUPER_ADMIN, DIRECTOR, BRANCH_MANAGER, RECEPTION_MANAGER учун.
- Case билан боғланган маълумотлар schema'даги Cascade орқали тозаланади.
- Applicant Client бошқа жойда ишлатилмаётган бўлса автомат тозаланади.
- AuditLog'да CASE_UPDATED ва CASE_DELETED қайдлари қолади.

Қўллаш тартиби:
1) Иккала файлни тегишли жойга алмаштиринг.
2) GitHub commit/push қилинг.
3) Railway backend ва CRM deploy тугашини кутинг.
4) Prisma db push КЕРАК ЭМАС — schema ўзгармаган.

Муҳим:
- Ўчириш "hard delete". Нотўғри ёки тест мурожаатлар учун ишлатинг.
- Тасдиқланган шартномаси бор ишни ўчиришдан олдин IDни қайта киритиш талаб қилинади.
